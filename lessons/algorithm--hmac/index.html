HMAC 密钥化哈希认证码

层级 2algorithm消息认证与 AEAD

这一课要解决什么

读完这一课，你能用自己的话解释「HMAC 密钥化哈希认证码」在密码学里解决什么问题、它依赖什么假设，以及至少一个会失效的边界。

算法 ：HMAC 密钥化哈希认证码（Hash-based Message Authentication Code）。留存 RFC 2104 文本在摘要段给出定义：「This document describes HMAC, a mechanism for message authentication using cryptographic hash functions.」其下一句交代它与密钥和哈希的结合方式：「HMAC can be used with any iterative cryptographic hash function, e.g., MD5, SHA-1, in combination with a secret shared key.…

为什么值得读

§1 说明其构造取向：「This document specifies HMAC using a generic cryptographic hash function (denoted by H).」并紧跟实例化要求：「Specific instantiations of HMAC need to define a particular hash function.」——文件定义的是与具体哈希无关的通用构造，实例化时才选定哈希。这解释了为什么要以 可替换底层哈希 的嵌套结构来做 MAC：既有软件里表现良好、代码随处可得的哈希函数无需改动即可复用。摘要段那句把强度前提也归到底层哈希：「The cryptographic strength of HMAC depends on the properties of the underlying hash function.」（front）。…

边界与攻击面

限度写在两处。§1 记底层哈希的现状：「MD5 has been recently shown to be vulnerable to collision search attacks [Dobb].」并限定其影响面：「This attack and other currently known weaknesses of MD5 do not compromise the use of MD5 within HMAC as specified in this document (see [Dobb]); however, SHA-1 appears to be a cryptographically stronger function.」——已知的 MD5 碰撞攻击当时尚未危及 HMAC 内的 MD5 使用，但 SHA-1 被评述为更强。…
