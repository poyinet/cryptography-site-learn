不经意传输

层级 4algorithm秘密共享与 MPC

这一课要解决什么

读完这一课，你能用自己的话解释「不经意传输」在密码学里解决什么问题、它依赖什么假设，以及至少一个会失效的边界。

算法 ：不经意传输（Oblivious Transfer）。1-out-of-2 OT 中，发送者持有 m0 与 m1，接收者持有选择位 b；协议结束时接收者得到 m b，但发送者不知道 b，接收者也得不到 m {1-b}。Rabin 的原始版本是“抛硬币式”OT：接收者以一半概率得到秘密。Even–Goldreich–Lempel 后来给出更常用的 1-out-of-2 形式。构造通常基于公钥加密、陷门置换或格假设。

为什么值得读

OT 是安全多方计算的“乘法门”：有了 OT，双方可以在不泄露输入的情况下计算电路。它也是隐私集合求交、 oblivious database access、密钥交换和隐私机器学习的基础。没有 OT，很多 MPC 协议只剩理论上的存在性。按“输入 → 状态 → 变换 → 输出 → 判据”复述机制；每一步都要能指出谁执行、改变什么、留下什么证据。无法指出证据的步骤，只能标为待核，不能写成已复现。

边界与攻击面

OT 的安全性取决于模型：半诚实模型只保证不主动作弊的参与方；恶意模型需要额外验证。接收者可能试图同时得到两条消息，发送者可能替换消息；不加认证的 OT 不能证明对方身份。实现中的选择偏差、时序和重放也会破坏隐私。 形式模型
