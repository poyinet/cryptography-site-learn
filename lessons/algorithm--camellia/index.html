Camellia 加密算法

层级 3algorithm对称分组密码

这一课要解决什么

读完这一课，你能用自己的话解释「Camellia 加密算法」在密码学里解决什么问题、它依赖什么假设，以及至少一个会失效的边界。

算法 ：Camellia 加密算法（Camellia）。Camellia 是 NTT 与三菱电机在 2000 年联合设计的 128 位分组密码，密钥长度为 128、192 或 256 位，接口与 AES 相同：固定 128 位块，三种密钥长度。它采用 Feistel 结构：128 位密钥运行 18 轮，192 位和 256 位密钥运行 24 轮；每 6 轮之后插入一层 FL/FL^-1，并在「before the first round and after the last round」（第一轮之前与最后一轮之后）各做一次 128 位白化。…

为什么值得读

RFC 3713 把 Camellia 的设计目标写成：「for both software and hardware implementations」（同时适合软件与硬件实现），可用于 32 位处理器、8 位处理器、智能卡、密码硬件和嵌入式系统；它的密钥建立时间很短，密钥敏捷性（key agility）优于 AES。RFC 还说明 Camellia 与 AES 具有相同的 128 位「block and 128/192/256-bit」（块与 128/192/256 位）密钥接口，但它是另一种算法。Camellia 在标准化评估中获得过明确认可：NESSIE 项目把它选为推荐的密码原语，日本 CRYPTREC 把它「in the list of cryptographic techniques for」（列入密码技术清单）用于电子政务系统。…

边界与攻击面

RFC 3713 的安全性表述是设计者的评估：它说 Camellia 不存在概率超过 2^-128 的差分或线性特征，并说设计考虑了高阶差分、插值、相关密钥和截断差分等攻击。这是 2004 年 RFC 的评估，不是对全部攻击模型的形式化证明，也不保证未来不会出现更好的分析方法。本文不把 RFC 3713 的差分/线性评估扩大成对全部攻击模型的绝对安全结论，也不引用未经本文核实的攻击论文来宣称 Camellia 已被攻破。192 位密钥的 KR 右半是右 64 位的按位补码，这是规范规定的密钥构造，不是实现可以省略的步骤；它意味着 192 位密钥的密钥材料不能按普通 256 位密钥的右 128 位来处理，实现若忽略补码步骤会得到错误子密钥。本文用 192 位官方向量验证这一细节。…
