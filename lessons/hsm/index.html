硬件安全模块

层级 2algorithm密钥管理

这一课要解决什么

读完这一课，你能用自己的话解释「硬件安全模块」在密码学里解决什么问题、它依赖什么假设，以及至少一个会失效的边界。

算法 ：硬件安全模块（Hardware Security Module）。定义句来自受控非密信息保护建议的讨论段：「Hardware security module (HSM) devices safeguard and manage cryptographic keys and provide cryptographic processing.」这一句把职责分成两半——既要管密钥，也要做运算；同一份文件的缩写表第 1866 行把 HSM 展开为 Hardware Security Module，别名因此有据。…

为什么值得读

为什么要这么一台装置，密钥管理建议给的是第 5.5.2 节对策清单里的第三条：它要求把明文形态的秘密密钥与私钥限制在受物理保护的容器之内。紧跟的一句原样引出，因为它点名了装置类别：「This includes key generators, key-transport devices, key loaders, cryptographic modules, hardware security modules (HSMs), and key-storage devices」。按字面读，HSM 在这份清单里是被列为容器之一，与密码模块并列而不是其上。…

边界与攻击面

限度要说清楚，而且只说这份报告说过的。报告没有把硬件模块写成一种免疫装置：它对硬件给的是要求而不是保证——定义句与用途句（第 444-447 行）之后空一行，第 449-450 行紧接着说硬件模块「must be upgraded or redesigned to support PQC algorithms, which often have larger key sizes and different computational requirements」，下一句（从第 450 行尾起，到第 455 行止）还要更新固件或硬件、让模块能高效执行抗量子运算。报告也没写这类装置会被怎样攻破，该条目因此不写攻破方式。还有两处容易误引的地方必须在这里交代：这份报告一共两次谈到侧信道，两处都不在说硬件模块。…
