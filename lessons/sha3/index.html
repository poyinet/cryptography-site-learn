SHA-3 与 Keccak

层级 3algorithm哈希

这一课要解决什么

读完这一课，你能用自己的话解释「SHA-3 与 Keccak」在密码学里解决什么问题、它依赖什么假设，以及至少一个会失效的边界。

算法 ：SHA-3 与 Keccak（SHA-3）。SHA-3 是 FIPS 202 定义的六函数家族：四个固定长度哈希函数 SHA3-224、SHA3-256、SHA3-384、SHA3-512，以及两个可扩展输出函数 SHAKE128、SHAKE256。它们都建立在 KECCAK-p[1600,24] 置换上：状态是 5×5 个 64 位 lane，共 1600 位；置换迭代 24 轮。SHA-3 采用海绵构造。设 rate 为 r 位、capacity 为 c 位，r + c = 1600。…

为什么值得读

SHA-3 的来源是 NIST 的公开 SHA-3 密码哈希算法竞赛：FIPS 202 明确说 SHA-3 基于 KECCAK，而 KECCAK 是 NIST 在该竞赛中选中的算法。Keccak 参考文档把 Keccak 定义为以 Keccak-f 置换和 pad10 1 为基础的海绵函数族；rate 与 capacity 的选择决定安全强度。海绵与 SHA-2 的 Merkle-Damgård 迭代不同：SHA-2 把链接值直接作为下一块输入并最终作为摘要，SHA-3 则把状态分成 rate 与 capacity，只从 rate 部分吸收/挤出，最终输出由状态挤出而不是直接暴露链接值。这种结构假设上的差异，使 SHA-3 在设计上能抵抗长度扩展等对 Merkle-Damgård 构造成立的攻击。capacity 是安全参数：capacity 越大，rate 越小，通用攻击的复杂度上界越高。…

边界与攻击面

SHA-3 目前是 NIST 批准的标准哈希家族，但这不等于没有攻击面。至少有三条边界需要理解。 长度扩展 ：FIPS 202 说 SHA-3 被设计为抵抗长度扩展等攻击。它与 Merkle-Damgård 哈希不同，不能把经典的 H(M pad(M) X) 长度扩展直接套用到 SHA-3 上；这是因为海绵只从 rate 部分吸收/挤出，capacity 不直接暴露。 容量限制 ：海绵的安全强度受 capacity 限制；把 SHAKE 的输出加长不会把安全强度提高到容量允许的上界以上。SHAKE128 的碰撞安全强度上限是 128 位，SHAKE256 是 256 位；输出长度 d 很小时，碰撞强度按 min(d/2, …) 下降。 XOF 的相关输出 ：SHAKE 的输出长度不影响已产生的前缀。…
