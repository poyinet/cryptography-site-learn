Blowfish 分组密码

层级 3algorithm对称分组密码

这一课要解决什么

读完这一课，你能用自己的话解释「Blowfish 分组密码」在密码学里解决什么问题、它依赖什么假设，以及至少一个会失效的边界。

算法 ：Blowfish 分组密码（Blowfish）。Blowfish 是 Bruce Schneier 在 1993 年提出的 64 位分组密码。它使用 16 轮 Feistel 网络，密钥长度最多 448 位；子密钥由 18 项（P1–P18）32 位 P 数组和四个 256 项 32 位 S-box 组成。F 函数把 32 位输入分成四个 8 位字节 a、b、c、d： text F(x) = ((S1[a] + S2[b] mod 2^32) XOR S3[c]) + S4[d] mod 2^32 加密把 64 位块分成 xL、xR。…

为什么值得读

Blowfish 的设计目标是快速、免费、无专利、简单、使用可变长度密钥（32–448 位），并用密钥相关 S-box 抵抗差分和线性分析；论文还要求平坦密钥空间和没有弱密钥。它不使用 DES 的位级置换，而是在 32 位字上使用异或、加法和表查找，适合 32 位处理器。它的数据加密很快，但密钥扩展很重：每个新密钥要执行 521 次加密。论文把它定位为公开、无专利的候选算法，而不是已发布标准；本文分析认为，需要频繁更换密钥的场景要权衡这一初始化成本。Blowfish 仍然是 64 位块。生日碰撞边界约为 2^32 个块，处理大量数据时会限制安全使用量。本文判断它适合作为历史和教学案例，不应默认用于新设计；新设计通常需要更大的块和 AEAD。

边界与攻击面

Blowfish 的块只有 64 位。HAC 的生日碰撞分析指出，n 位块在约 2^(n/2) 个块后出现匹配；对 64 位块约为 2^32 个块。本文分析认为，大量数据下这限制了 Blowfish 的安全使用量。 密钥扩展成本 521 次加密的密钥扩展让更换密钥变得昂贵。论文把它视为对暴力搜索的额外成本；本文分析认为，在高密钥周转的系统中这也是实际负担，子密钥应按密钥材料保护，不能把 4168 字节的表当成公开数据。 密钥相关 S-box 与侧信道 密钥相关 S-box 提高了差分和线性分析的难度，但实现仍要按字节索引四个表；本文分析认为，缓存、时序或故障注入可能泄露与密钥相关的访问模式。本文的教学实现不是常量时间，也不测试侧信道。 无完整性 Blowfish 只定义分组密码，不提供完整性或认证。翻转密文会改变对应明文，但 Blowfish 本身无法检测；本文建议需要认证时使用 AEAD 或加密后再 MAC。…
