SM3 杂凑算法

层级 2standard中国国密

这一课要解决什么

读完这一课，你能用自己的话解释「SM3 杂凑算法」在密码学里解决什么问题、它依赖什么假设，以及至少一个会失效的边界。

标准 ：SM3 杂凑算法（SM3 Cryptographic Hash Algorithm）。 512 位分组与 256 位摘要 SM3 采用 512 位分组、132 字消息扩展和 64 轮压缩，把消息压成 256 位摘要。它接受长度小于 2^64 比特的消息；填充规则是：先补一个 1，再补最少的 0 使长度模 512 余 448，最后补 64 位消息长度。 消息扩展与 64 轮压缩 每个 512 位块先拆成 16 个 32 位字 W0…W15，再扩展出 W16…W67 和 W’0…W’63，共 132 个字。…

为什么值得读

SM3 是中国商用密码体系的杂凑底座。SM2 签名先把用户身份和曲线参数压成 ZA，再计算 e = SM3(ZA M)；证书指纹、TLCP 的 PRF/HMAC、代码完整性和审计记录也都依赖 SM3。它把任意长度输入压成 256 位摘要，给签名、认证和完整性校验提供统一入口。没有 SM3，SM2 的签名和 TLCP 的密钥派生就无法形成闭环。

边界与攻击面

SM3 的设计目标是 256 位杂凑，通用生日界约 2^128；公开的缩轮分析不等于全轮破译。现实风险更多来自构造错误：长度扩展、MAC 拼接、截断输出、侧信道，以及把 SM3 与 SHA-256 混用导致协议不一致。
