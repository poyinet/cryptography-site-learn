KMAC / cSHAKE 族

层级 3term消息认证与 AEAD · 哈希

这一课要解决什么

读完这一课，你能用自己的话解释「KMAC / cSHAKE 族」在密码学里解决什么问题、它依赖什么假设，以及至少一个会失效的边界。

术语 ：KMAC / cSHAKE 族（KMAC / cSHAKE）。SP 800-185 定义一组由 KECCAK 派生的函数。摘要称 cSHAKE「is a customizable variant of the SHAKE function, as defined in Federal Information Processing Standard (FIPS) 202」，其计算把 encode string(N) 与 encode string(S) 一并做字节填充后再接输入。…

为什么值得读

定制分两个串：N 是「function-name bit string, used by NIST to define functions based on cSHAKE」，S 是用户自选的 customization 串；当两者都为空时 cSHAKE 等价于 SHAKE，即 cSHAKE128(X, L, "", "") = SHAKE128(X, L)。§3.4 警告用户不得自造 N 值，否则「could cause interoperability problems with future NIST-defined functions」。KMAC 与 SHAKE/cSHAKE 的区别在于「altering the requested output length generates a new, unrelated output」。

边界与攻击面

密钥与输出长度是主要误用点。§8.4.1 规定「shall not select an input key, K, whose length is less than their required security strength」；§8.4.2 规定用作 MAC 时输出长度不得小于 32 位，选择小于 64 位必须先做仔细的风险评估；§8.3 针对碰撞与原像说明这类函数无论输出多长都可能以 2 的 128 次方工作量被攻破，「a longer output does not, in general, improve its security against these attacks」。KMAC 的密钥 K 允许任意长度包括零长度，因此批准用途须自行满足密钥长度下限。
