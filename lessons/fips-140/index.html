密码模块标准（FIPS 140）

层级 3term应用安全工程 · 密钥管理

这一课要解决什么

读完这一课，你能用自己的话解释「密码模块标准（FIPS 140）」在密码学里解决什么问题、它依赖什么假设，以及至少一个会失效的边界。

为什么值得读

标准把要求组织为十一个领域：模块规范、接口、角色服务与认证、软件/固件安全、运行环境、物理安全、非侵入式安全、敏感安全参数管理、自测试、生命周期保障与其他攻击缓解；§1 说明「Four security levels were specified for each of eleven requirement areas」。¶7 要求所选安全级别与应用的 security requirements of the application and environment 相称，并且某个级别的要求包含该级特有要求加上对所有模块通用的要求。FIPS 140-3 与 ISO/IEC 19790:2012/Cor.1:2015 与 ISO/IEC 24759:2017 对齐（§2）。

边界与攻击面

标准自身在 ¶13 声明符合性不等同于安全：「conformance to this standard is not sufficient to ensure that a particular module is secure」，并规定标准至少每五年复审。¶7 把级别选择的责任交给使用方，级别只是定性分档；¶6 允许已经批准用于涉密用途的模块替代按本标准验证的模块，因此已通过 140-3 并非唯一可用路径。
