XSalsa20 流密码

层级 3algorithmOTP 与流密码

这一课要解决什么

读完这一课，你能用自己的话解释「XSalsa20 流密码」在密码学里解决什么问题、它依赖什么假设，以及至少一个会失效的边界。

算法 ：XSalsa20 流密码（XSalsa20）。 Salsa20 的 512 位状态 Salsa20 把 256 位密钥、64 位 nonce、64 位块计数器和 128 位常量排成 16 个 32 位字的 4×4 矩阵。20 轮 ARX（32 位加、旋转、异或）后，把结果加回输入，得到 64 字节密钥流块。它没有 S 盒，也没有秘密下标查表。 XSalsa20 先派生子密钥 XSalsa20 把 nonce 扩到 192 位：先用密钥和前 128 位 nonce 跑 HSalsa20。…

为什么值得读

XSalsa20 的动机是 nonce 管理，而不是新的轮函数。NaCl 的 crypto box 用 X25519 协商密钥、XSalsa20 加密、Poly1305 认证；每条消息可以独立随机 192 位 nonce，不需要跨会话共享计数器。它保持 Salsa20 的速度和 ARX 的侧信道特性，只增加一次 HSalsa20 子密钥派生，成本小于一个 Salsa20 输出块。SKEW 2011 的论文证明：对 XSalsa20 的快速攻击可以转化为对 Salsa20 的攻击，因此它的安全性归约到 Salsa20。

边界与攻击面

XSalsa20 只提供机密性，不提供完整性；必须配 Poly1305 或上层 AEAD。nonce 仍然必须唯一：同一 key/nonce 重用会让两条密钥流相同，密文异或即明文异或。192 位 nonce 只是把碰撞概率降到可接受水平，不是允许重复使用。64 位块计数器给单对 key/nonce 约 2^64 个 64 字节块的上限；超过后计数器回绕，必须换 key 或 nonce。ARX 软件实现天然抵抗计时攻击，但硬件功耗/电磁分析仍可能恢复状态；HSalsa20 也不是通用 KDF，不应把同一密钥跨用途复用。
