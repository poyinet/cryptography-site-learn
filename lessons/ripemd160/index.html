RIPEMD-160 散列

层级 3algorithm哈希

这一课要解决什么

读完这一课，你能用自己的话解释「RIPEMD-160 散列」在密码学里解决什么问题、它依赖什么假设，以及至少一个会失效的边界。

算法 ：RIPEMD-160 散列（RIPEMD-160）。RIPEMD-160 是输出 160 位摘要的迭代哈希函数，处理 32 位字与 512 位消息块；状态是 5 个 32 位字 h0…h4。初始值是 h0=67452301、h1=efcdab89、h2=98badcfe、h3=10325476、h4=c3d2e1f0。填充与 MD4 相同：先追加 0x80，再补 0 位到长度对 512 同余于 448，最后追加 64 位小端消息长度。…

为什么值得读

RIPEMD 是在欧盟 RIPE（RACE Integrity Primitives Evaluation）项目中开发的；RIPEMD-160 是 1996 年提出的加强版本。论文同时提出 160 位的 RIPEMD-160 和作为 RIPEMD 替代的 128 位 RIPEMD-128；160 位版本的设计目标是把 RIPEMD 已积累的信任转移到新算法上。两条线路使用相同的五个函数但顺序相反（右线用 f(79−j)），并使用不同的常量、消息顺序和旋转量；攻击者要同时控制两条线才能构造碰撞，这提高了差分攻击的难度。设计目标是让两条线路尽可能不同，而不是让它们各自独立运行。160 位摘要的理想碰撞复杂度约为 2^80，原像/第二原像约为 2^160；论文把 160 位结果作为对原 128 位 RIPEMD 的安全加强。…

边界与攻击面

RIPEMD-160 采用 Merkle-Damgård 迭代：每块处理后的链接值就是下一块的输入，最终输出也是链接值；因此给定 H(M) 与 M 的长度，可以做长度扩展，得到 H(M pad(M) X)，这不是碰撞。本批次演示：已知 RIPEMD-160(abc) 的结果与 64 字节填充长度，不知道原消息也能计算 RIPEMD-160( abc pad extra ) = 1f35150185a2c3cfc80d435934579261c99da3e0 。160 位摘要的生日碰撞界约为 2^80；这一数字是通用攻击的上界，不代表对 RIPEMD-160 的具体密码分析结果。2004 年 Wang、Feng、Lai、Yu 的 ePrint 2004/199 标题列出 MD4、MD5、HAVAL-128 与 RIPEMD；标题只写 RIPEMD，没有写 RIPEMD-160。…
