RC5 分组密码

层级 3algorithm对称分组密码

这一课要解决什么

读完这一课，你能用自己的话解释「RC5 分组密码」在密码学里解决什么问题、它依赖什么假设，以及至少一个会失效的边界。

算法 ：RC5 分组密码（RC5）。RC5 是一种参数化分组密码，记作 RC5-w/r/b：w 是字长（16、32 或 64 位），r 是轮数，b 是密钥字节数。块大小是 2w 位；常用的 RC5-32 使用两个 32 位字 A 和 B，块大小 64 位。Rivest 把 RC5-32/12/16（32 位字、12 轮、16 字节密钥）作为标称参数集。RC5 的密钥扩展把 b 字节密钥转成 c 个字 L，并生成 T = 2(r+1) 个轮密钥字 S。…

为什么值得读

RC5 的设计目标是小、快、简单，并且可参数化。它没有 S-box 和查找表，轮函数只有加法、异或和数据相关旋转，适合硬件和软件实现；参数 w、r、b 让用户可以在块大小、轮数、密钥长度和性能之间取舍。数据相关旋转让轮函数带有非线性：旋转量不是固定常数，而是来自另一半数据。它使 RC5 的扩散和差分行为与固定旋转的 ARX 密码不同，也让时序和功耗分析成为实现层的重要问题。RC5 的历史地位还在于它是 RC6 的前身。RC6 在 1998 年进入 AES 竞选的最后一轮，后来 AES 选择了 Rijndael；RC5 本身没有被标准化为现代通用分组密码，但它是理解 ARX 参数化和数据相关旋转的重要样本。

边界与攻击面

RC5-32 的块只有 64 位。与 128 位块相比，生日碰撞意义下的安全边界更窄；处理大量数据时，64 位块会限制可安全加密的块数。RC5-64 的块更大，但轮数和实现成本也更高。 数据相关旋转与侧信道 RC5 的旋转量来自数据，软件实现可能因旋转量不同而产生时序差异；硬件实现也可能在功耗或电磁辐射上泄露旋转量。常量时间实现、掩码和故障防护属于实现层，不在算法定义内。 参数选择 RC5 的安全性依赖 w、r、b 的选择。Rivest 明确警告，过小的轮数或不合适的参数会提供很弱的安全性；标称 RC5-32/12/16 只是建议起点，不是对所有威胁模型都足够。参数必须在设计时固定，不能由接收方在运行时任意选择。 无完整性 RC5 只提供分组密码的伪随机置换，不提供完整性。翻转密文会改变对应明文，但 RC5 本身无法检测；需要认证时应使用 AEAD 或加密后再 MAC。…
