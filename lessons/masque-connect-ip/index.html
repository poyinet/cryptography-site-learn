MASQUE CONNECT-IP

层级 3protocol协议与 PKI

这一课要解决什么

读完这一课，你能用自己的话解释「MASQUE CONNECT-IP」在密码学里解决什么问题、它依赖什么假设，以及至少一个会失效的边界。

协议 ：MASQUE CONNECT-IP（MASQUE Proxying IP over HTTP）。RFC 9484 的自述分三句：「This document describes how to proxy IP packets in HTTP.」「This protocol is similar to UDP proxying in HTTP but allows transmitting arbitrary IP packets.」以及「More specifically, this document defines a protocol that allows an HTTP client to create an IP tunnel thr…

为什么值得读

它补的是 CONNECT-UDP 之外的通用性缺口：摘要说明本协议允许「transmitting arbitrary IP packets」，因此可承载非 UDP 的协议族；同段还声明对基础件的更新关系——「This document updates RFC 9298.」

边界与攻击面

这份文件规定怎么代理 IP 包，但把部署责任留给运营方：§11 给出建议级要求——「HTTP servers that support IP proxying SHOULD restrict its use to authenticated users」，§4.6 提供收窄请求范围的手段（客户端可把请求限制到特定 IP 前缀或协议）。也就是说 放行什么 不由本文件硬性规定，而由 SHOULD 级配置与范围限制共同承担。
