Halo2 证明系统

层级 4algorithm零知识证明

这一课要解决什么

读完这一课，你能用自己的话解释「Halo2 证明系统」在密码学里解决什么问题、它依赖什么假设，以及至少一个会失效的边界。

算法 ：Halo2 证明系统（Halo2）。 PLONKish 矩阵 Halo2 把电路写成矩阵：列分 advice、fixed、instance 三类，行是门。每个门用多项式约束把相邻行、多个列连起来；custom gate 允许一个门同时读多列，lookup argument 把某列的值约束到一张表里。行数取 2^k，在单位根域上做多项式插值，约束在整域上为零。 置换、lookup 与 IPA copy constraint 用 permutation argument 强制两格相等；range check 用 lookup 查表。…

为什么值得读

Halo2 不需要 trusted setup：公共参数由固定曲线生成，不存在“toxic waste”。PLONKish 的列和门可以按电路定制，lookup 让 8 位/16 位范围检查不必写成一长串约束；IPA 只依赖离散对数，不引入配对曲线。递归组合让证明可以验证证明，适合 rollup 和隐私池这类多层电路。 代价 透明设置不是免费的：IPA 的证明和验证比 Groth16 重，递归验证器本身要占不少行。Halo2 把“设置阶段的一次性风险”换成“证明阶段的持续计算成本”，适合电路多、迭代快、无法办可信仪式的团队。

边界与攻击面

Halo2 没有可信设置，不等于没有信任：约束系统、lookup 表和公开输入由应用方定义，门写错或漏约束会让证明“证明了一个错误陈述”。IPA 的验证不是常数大小，递归验证器要吃掉不少行；证明时间与电路规模、列数和 lookup 数量线性相关。它也不自动提供“输入隐私”，公开输入仍然公开。 工程风险 Halo2 的电路需要手工安排列、行和门，列数不足会让电路膨胀，lookup 表过大会拖慢证明。参数（k、列数、lookup 位宽）选错会造成性能断崖；升级库版本也可能改变 transcript 或参数，必须重新做可信度评估。
