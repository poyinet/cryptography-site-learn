国密 JSON Web 语法

层级 4standard中国国密

这一课要解决什么

读完这一课，你能用自己的话解释「国密 JSON Web 语法」在密码学里解决什么问题、它依赖什么假设，以及至少一个会失效的边界。

标准 ：国密 JSON Web 语法（Chinese JSON Object Signing and Encryption）。GM/T 0125.2—2022 的 JWS 由 JOSE 头部、有效载荷和签名组成。保护头部先 \(UTF8\) 再 \(base64url\)：\(protected\ b64=base64url(UTF8(header))\)；有效载荷编码为 \(payload\ b64=base64url(payload)\)。签名输入是 \(M=ASCII(protected\ b64\ \text{“.”}\ payload\ b64)\)。…

为什么值得读

国密 JOSE 不是“把 JWT 换个签名算法”那么简单。它把 \(alg\) 作为算法标识，把 \(kid/jwk/x5c/x5t sm3\) 作为密钥标识，把保护头部与无保护头部分开；验证时如果只读 \(alg\) 字符串、不校验密钥类型，就会重演 JWS 算法混淆。公式化的关键是把“签名输入”“签名值编码”“密钥绑定”三件事分开：签名输入固定为保护头部编码、点、载荷编码；SM2 输出 DER；HMAC 输出 256 位；验证条件是 \(alg\in Allow(key)\) 且 \(key=KeyStore[Id]\)。

边界与攻击面

边界有四条。第一，无保护头部不进入签名，攻击者可以改它；任何影响安全决策的头部都应放进保护头部。第二，\(alg\) 与密钥类型必须绑定：把 SM2 公钥当 HMAC 密钥、或接受 \(none\)，都会破坏验证。第三，base64url 必须去 padding 且按标准解码，JSON 序列化中重复头部参数应拒绝。第四，SM2 签名值按 DER 编码，长度不是固定 64 字节；实现不能把 DER 当固定长度切片。标准不规定 JWT 声明语义、密钥生命周期或侧信道防护。
