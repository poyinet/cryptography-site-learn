BLAKE3 散列

层级 3algorithm哈希

这一课要解决什么

读完这一课，你能用自己的话解释「BLAKE3 散列」在密码学里解决什么问题、它依赖什么假设，以及至少一个会失效的边界。

算法 ：BLAKE3 散列（BLAKE3）。BLAKE3 是单算法哈希函数：默认输出 256 位，支持任意长度输出（0 ≤ d < 2^64），并提供 hash、keyed hash 与 derive key 三种模式。它把输入按 1024 字节切成 chunk；chunk 作为二叉树的叶子，左子树满且大于等于右子树，父节点把两个子节点的链接值合并。输入按 64 字节块压缩。压缩函数的状态 v0…v15 由 8 个链接字、4 个 IV 字、64 位计数器 t0/t1、块字节数 b 和域标志 d 组成；IV0…IV7 与 BLAKE2s 相同。它基于 BLAKE2s 的 32 位混合逻辑，但只做 7 轮而不是 BLAKE2s 的 10 轮。…

为什么值得读

BLAKE3 是 BLAKE2 的演进：它把 BLAKE2s 的 32 位混合逻辑保留下来，但把轮数从 10 降到 7，并用树结构获得并行性，而不是像 BLAKE2 那样提供多个面向不同平台的变体。BLAKE2 于 2012 年公布，RFC 7693 于 2015 年 11 月规定 BLAKE2b 与 BLAKE2s；本批次使用的 BLAKE3 规范版本为 20211102173700。BLAKE3 的目标安全强度是 128 位，默认输出 256 位。7 轮选择基于既有 BLAKE/BLAKE2 密码分析；规范第 4 节给出 128 位安全目标、压缩函数分析与模式论证。树结构提供无界并行度，并支持可验证流式传输与增量更新；这是 BLAKE3 相对 BLAKE2 的主要新能力。…

边界与攻击面

BLAKE3 的安全性建立在规范给出的 128 位安全目标、压缩函数分析与模式论证，以及现有 BLAKE/BLAKE2 分析上。实现错误（如 chunk/tree 边界或 flag 组合）会产生错误结果，而不是 接近正确 的结果。 XOF 输出长度 ：BLAKE3 不对不同输出长度做域分离：较短输出是较长输出的前缀；输出长度因此不是独立的域标签。需要不同域时，应使用 keyed hash 或 derive key，而不是改变输出长度。 带密钥模式 ：keyed hash 的安全性依赖密钥保密与均匀随机；密钥必须是 256 位，实践中不应把无密钥 hash 直接当 MAC。derive key 通过 context 与 material 两阶段分离不同用途；context 应硬编码、全局唯一且应用特定，不能包含盐、ID 或当前时间等可变数据。…
