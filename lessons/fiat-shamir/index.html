Fiat-Shamir 启发式

层级 3algorithm零知识证明

这一课要解决什么

读完这一课，你能用自己的话解释「Fiat-Shamir 启发式」在密码学里解决什么问题、它依赖什么假设，以及至少一个会失效的边界。

算法 ：Fiat-Shamir 启发式（Fiat-Shamir Heuristic）。Fiat–Shamir 是密码学里最常用、也最常被误用的一个 转换技巧 ：它把一个 交互式 的协议，变成一个 非交互式 的证明或签名。 典型的 σ-协议（交互式） 长这样： 1.证明者（知道证人 w）发送一个 承诺 a； 2.验证者（只知道陈述 x）随机挑一个 挑战 c； 3.证明者回应 z； 4.验证者检查某个方程是否成立（例如 g^z = a · x^c ）。这里的关键是： 挑战 c 由验证者随机产生 ，所以证明者无法提前挑选一个对自己有利的 c。…

为什么值得读

没有 Fiat–Shamir，就没有今天的数字签名。 数字签名的定义要求「签名者对着消息签名，验证者事后单独验证」。 但密码学能构造出来的、最好用的那批身份识别协议，全都是交互式的 ——Schnorr 的识别方案就是交互式的，ElGamal 也是。如果只能靠交互来完成认证，公钥密码在最需要它的地方（软件更新、证书、交易、区块）就全都用不上。Fiat–Shamir 的贡献是 一次去掉交互 ，而且代价极小：多一次哈希调用。 它是密码学里复用率最高的想法 ： - 签名 ：Schnorr 签名 → DSA、ECDSA、Ed25519、BIP 340、ML-DSA。- 非交互式零知识证明 ：Schnorr 的离散对数知识证明是 NIZK 的教科书例子；Bulletproofs 一类方案也建立在它上面；区块链上验证「我知道某个秘密」的脚本，多半就是它。…

边界与攻击面

Fiat–Shamir 没有被「破」，但它是密码学里被误用最多、后果最隐蔽的机制之一。以下每一条都对应过真实的安全事故或已发表的改进。 - 「弱 FS」= 可延展 。如果挑战只哈希承诺而不哈希陈述（ c = H(a) 而不是 c = H(x a) ），整个变换就是可延展的：攻击者可以把一个签名改造成另一个合法签名。 把公钥漏在挑战之外，正是 Schnorr 家族关联密钥攻击的根源 ，也是 BIP 340 坚持 key prefixing 的原因。 规则很简单：公钥、会话标识、消息、所有承诺，一个都不能少。 - 原始 Fiat–Shamir 论文的证明是错的 。1986 年那篇 STOC 论文的 Lemma 6 隐式依赖了 9 年后才出现的 forking lemma；Bellare 与 Rogaway 1993 在证明 FS 作为证明系统时，也只是断言了可靠性而没有证明。…
