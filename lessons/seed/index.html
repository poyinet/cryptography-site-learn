SEED 韩国内对称加密

层级 3algorithm对称分组密码

这一课要解决什么

读完这一课，你能用自己的话解释「SEED 韩国内对称加密」在密码学里解决什么问题、它依赖什么假设，以及至少一个会失效的边界。

算法 ：SEED 韩国内对称加密（SEED）。SEED 是 128 位分组密码，密钥长度也是 128 位，采用 16 轮 Feistel 结构。128 位输入分成左右各 64 位的 L、R，右半 R 送入带 64 位子密钥的轮函数 F。第 1 到第 15 轮做交换和混合，第 16 轮只更新 L、不再交换： text for i = 1..15: T = R R = L XOR F(Ki, R) L = T L = L XOR F(K16, R) C = L R 解密是加密的逆过程：使用同一轮结构，但按 K16、K15、…、K1 的顺序使用子密钥。…

为什么值得读

RFC 4269 说 SEED 由韩国信息安全局（KISA）自 1998 年起开发，是韩国国家标准算法，规范性引用为 TTAS.KO-12.0004（1998 年 9 月）。它使用与当时计算技术相称的 S-box 和置换，采用 16 轮 Feistel 结构，并声称能抵抗差分分析、线性分析和相关密钥分析。RFC 4010 补充了实现层面的设计目标：SEED 在软件和硬件中都容易实现，内存占用比一些算法小，密钥生成不降低安全性，适合「such as mobile devices and smart cards」（移动设备与智能卡）等资源受限环境。它还称 SEED 是韩国国家工业协会标准，经过公开评审，被 ISO/IEC JTC 1/SC 27 和日本 CRYPTREC 认为密码学上是安全的，并广泛用于韩国电子商务和金融服务。…

边界与攻击面

RFC 4269 第 3 节的实质性安全表述只有「No security problem has been found on SEED.」这一句（没有发现 SEED 的安全问题）；RFC 4010 则说 SEED 能抵抗差分、线性和相关密钥分析，并被 ISO/IEC JTC 1/SC 27 和 CRYPTREC 认为安全。这些都是 2005 年文档中的评估，不是对全部攻击模型的形式化证明，也不保证未来不会出现更好的分析方法。本文不把它们扩大成绝对安全结论，也不引用未经本文核实的攻击论文来宣称 SEED 已被攻破。RFC 4269 废止 RFC 4009 的原因是 RFC 4009 的 F 函数和 SS-box 定义有歧义，而不是算法被攻破；算法本身没有改变。实现者应以 RFC 4269 的清晰定义为准，避免照抄旧伪代码。…
