MACsec 链路加密（IEEE 802.1AE）

层级 3standard消息认证与 AEAD

这一课要解决什么

读完这一课，你能用自己的话解释「MACsec 链路加密（IEEE 802.1AE）」在密码学里解决什么问题、它依赖什么假设，以及至少一个会失效的边界。

标准 ：MACsec 链路加密（IEEE 802.1AE）（MACsec link encryption (IEEE 802.1AE)）。 在以太网帧里加一层安全头 MACsec 在源 MAC 地址之后插入 SecTAG，在帧尾加 ICV，可选加密帧体。SecTAG 为 8 或 16 字节：2 字节 EtherType 0x88E5、1 字节 TCI/AN、1 字节 SL、4 字节 PN，以及可选的 8 字节 SCI。SCI 由 48 位 MAC 与 16 位端口号组成，用来标识单向安全信道。 密码套件 当前标准以 AES-GCM 为主：GCM-AES-128 为必选，GCM-AES-256 与 GCM-AES-XPN-128/256 为可选。…

为什么值得读

MACsec 保护的是链路层帧，因此以太网上的 ARP、LLDP、IP、MPLS 等都被同一层覆盖，不依赖上层协议是否启用 TLS/IPsec。它适合交换机到交换机、路由器到路由器、数据中心叶脊链路，以及需要线速加密的承载网。 为什么还需要 MKA MACsec 只定义帧保护，密钥协商在 IEEE 802.1X-2010 的 MACsec Key Agreement（MKA）。设备用长期 CAK 认证，选举密钥服务器，由服务器生成并分发短期 SAK；SAK 轮换不中断链路，AN 两位允许一个安全信道同时保有 4 个安全关联。

边界与攻击面

接收端验证 ICV，失败即丢帧；PN 递增，replay window 允许一定乱序但拒绝过旧帧。SecTAG 的 SL 处理短帧，confidentiality offset 可选择只加密帧体的一部分（0/30/50 字节偏移），以兼顾某些协议头可见的需求。 不是万能加密 MACsec 的保护范围止于链路层，不能防止链路两端设备内部泄露，也不能替代终端加密。它依赖正确的 MKA 配置、CAK 保护和 SAK 轮换；配错密钥、关闭验证或过大的 replay window 都会削弱安全性。ICV 长度可为 8 或 16 字节，实际部署多采用 16 字节（128 位）。
