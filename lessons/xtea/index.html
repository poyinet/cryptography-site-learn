XTEA 扩展 TEA

层级 3algorithm对称分组密码

这一课要解决什么

读完这一课，你能用自己的话解释「XTEA 扩展 TEA」在密码学里解决什么问题、它依赖什么假设，以及至少一个会失效的边界。

算法 ：XTEA 扩展 TEA（XTEA）。XTEA 是 Needham 和 Wheeler 对 TEA 的扩展。它保持 64 位块和 128 位密钥，把密钥分成四个 32 位字 k0、k1、k2、k3；循环数 N 是参数，论文推荐 32 个循环。每个循环更新 v0 和 v1 各一次，因此包含 64 次字更新，通常称为 64 轮。 text v0 += (((v1 << 4) ^ (v1 5)) + v1) ^ (sum + key[sum & 3]) sum += delta v1 += (((v0 << 4) ^ (v0 5)) + v0) ^ (sum + key[(sum 11) & 3]) 其中 delta = 0x9e3779b9，sum …

为什么值得读

XTEA 的重要性在于它如何修复 TEA 的两个小弱点。TEA 的混合部分看起来未被破坏，但相关密钥攻击是可能的；TEA 的有效密钥长度是 126 位而非 128 位。XTEA 的密钥调度和密钥引入改动针对这两点。论文称这些改动修复了弱点，同时保留几乎相同的简单性、很少的初始化、较多循环和不复杂分析的设计目标。这是设计声明，不是完整安全证明。32 个循环是论文推荐值；每个循环包含两次更新，所以通常称为 64 轮。XTEA 仍然使用 64 位块，生日碰撞边界约为 2^32 个块，处理大量数据时会限制安全使用量。本文判断它不是现代标准算法，适合作为历史和教学案例，不应默认用于新设计。

边界与攻击面

XTEA 的块只有 64 位。HAC 的生日碰撞分析指出，n 位块在约 2^(n/2) 个块后出现匹配；对 64 位块约为 2^32 个块。大量数据下，这限制了 XTEA 的安全使用量。 相关密钥与设计声明 TEA 的相关密钥攻击和 126 位有效密钥问题促使 XTEA 修改密钥调度和密钥引入。论文说 TEA 的混合部分看起来未被破坏，但相关密钥攻击是可能的（在两个相关密钥下构造 2^32 个文本看起来并不实际）；126 位有效密钥主要影响某些应用，而不是简单加解密。论文称这些改动修复了两个弱点；这是设计目标，不是完整安全证明。本文不复述未引用的缩减轮攻击，也不把修复 TEA 弱点等同于 XTEA 对所有攻击安全。 无完整性 XTEA 只定义分组密码，不提供完整性或认证。翻转密文会改变对应明文，但 XTEA 本身无法检测；需要认证时应使用 AEAD 或加密后再 MAC。…
