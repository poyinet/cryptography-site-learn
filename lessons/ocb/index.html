OCB 偏移密码块模式

层级 3algorithm消息认证与 AEAD

这一课要解决什么

读完这一课，你能用自己的话解释「OCB 偏移密码块模式」在密码学里解决什么问题、它依赖什么假设，以及至少一个会失效的边界。

算法 ：OCB 偏移密码块模式（Offset Codebook）。 偏移与一次通过 OCB3 用 nonce N 派生一串偏移 Δ[i]，每个明文块先 XOR 偏移，再过分组密码，得到密文块；同时把明文块累加进校验和。最后一个块用特殊偏移和长度处理，最终标签由校验和再加密并 XOR 偏移得到。 关联数据 AD 不加密，但会被带偏移的 MAC 结构压成一个值，最后并入标签。OCB 只需要分组密码的加密方向，所有块可以并行；一个密钥、一次通过，密文只增加标签长度。 参数 RFC 7253 要求 128 位分组，nonce 最长为 120 位（实际推荐 96 位），标签长度可配；AES-OCB 常用 128 位标签，TLS 草案用 96 位。…

为什么值得读

OCB 的卖点是一次通过、单密钥、可并行：认证嵌进加密，避免 Encrypt-then-MAC 的两次遍历和两把密钥。在支持 AES 指令的 CPU 上，OCB 的吞吐接近 CTR，适合低延迟网络和嵌入式设备。它也是 AEAD 历史上的关键方案：OCB1 2001，OCB3 2011，RFC 7253 2014；OCB2 在 2019 年被证明完全不安全，说明“版本”必须写清楚，不能把 OCB2 当 OCB3 用。

边界与攻击面

OCB 是 nonce-respecting AEAD：同一 key/nonce 加密两条不同消息会同时破坏机密性和认证，攻击者可恢复认证密钥并伪造后续消息。RFC 7253 明确说这种场景应改用 SIV。实现边界：nonce 计数器分区；标签长度绑定；密钥用量上限 2^48 块；解密先验标签；OCB2 的 2019 攻击说明版本和实现必须锁定 OCB3。
