SM9 标识密码算法

层级 3standard中国国密

这一课要解决什么

读完这一课，你能用自己的话解释「SM9 标识密码算法」在密码学里解决什么问题、它依赖什么假设，以及至少一个会失效的边界。

标准 ：SM9 标识密码算法（SM9 Identity-Based Cryptography Algorithm）。 配对与系统参数 SM9 使用双线性配对 e:G1×G2→GT。密钥生成中心持有主私钥 ks，计算系统公钥 Ppub=ksP2。用户标识 ID 与 hid 经 H1 映射到标量，用户私钥为 d {ID}=ks·(H1(ID‖hid,N)+ks)^{-1} mod N·P1。 签名 签名者取随机 r，计算 w=e(P1,Ppub)^r、h=H2(M‖w,N)、l=(r−h) mod N，若 l=0 重取；签名 S=l·d ID，输出 (h,S)。…

为什么值得读

SM9 把公钥直接绑定到标识，不需要证书链；密钥生成中心负责派生用户私钥。它适合邮件、专网与需要简化证书管理的场景。SM9 是标识密码；SM2 是证书式椭圆曲线公钥算法，SM4 是分组密码。SM9 的信任根在 KGC，和 SM2 的证书信任模型不同。

边界与攻击面

1.密钥托管：KGC 能派生任何用户私钥，必须作为信任根审计；主密钥泄露会瓦解全系统。2.配对实现：配对运算的时序、缓存与故障可泄漏私钥或伪造签名。3.标识与参数：hid、曲线、哈希或编码不一致会导致互操作失败或跨域攻击。4.协议层：不绑定标识、不检查 C1 与 KDF 输出，可能遭替换或解密错误。
