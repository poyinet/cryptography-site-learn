Boneh-Lynn-Shacham Short Signatures

这一课要解决什么

By the end, you can explain what “Boneh-Lynn-Shacham Short Signatures” solves, which assumption it relies on, and at least one boundary where it fails.

Algorithm : Boneh-Lynn-Shacham Short Signatures (BLS 短签名). Pairing and short signatures BLS works on a pairing-friendly curve: private key sk, public key PK=sk·P2, signature σ=sk·H(m), where H hashes the message to G1. Verification checks e(σ,P2)=e(H(m),PK). On BLS12-381, a signature is 48 bytes and a public key is 96 bytes.…

为什么值得读

BLS’s value is signature aggregation: n validators, transactions or votes occupy one signature, so bandwidth and storage grow sublinearly in n. It is deterministic, non-malleable and batch-verifiable with multi-pairings, fitting consensus votes, certificate transparency and light clients.…

边界与攻击面

BLS aggregation is “signatures add”, but protocol mistakes dominate: a rogue-key attack can cancel honest signatures with a crafted public key; checking only the aggregate equation without the message set can accept forgeries. Boundaries: BLS is not post-quantum; pairing parameters and subgroup checks must be correct; identity/zero-signature attacks require rejecting identity PK and σ; aggregate security depends on t…
