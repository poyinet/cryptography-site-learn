Tight Reduction

Level 4theorem理论基础

这一课要解决什么

By the end, you can explain what “Tight Reduction” solves, which assumption it relies on, and at least one boundary where it fails.

Theorem : Tight Reduction (紧致归约). A reduction turns “break the scheme” into “solve the assumption” A tight reduction does not prove a scheme secure directly. It proves: if a polynomial-time adversary A breaks the scheme with advantage ε, then a polynomial-time algorithm B solves the underlying assumption with advantage about ε/ℓ…

为什么值得读

Suppose the target is 128-bit security. If the reduction loses q s=2^40, the underlying assumption must provide about 168-bit security for the scheme to reach 128 bits; this changes group sizes, modulus lengths and performance. Multi-user settings are worse: if ℓ equals the number of users, deploying 2^20 users loses 20 bits. An asymptotic proof only says “polynomial reduction”; it does not give parameters.…

边界与攻击面

1. The reduction is not polynomial-time. If B enumerates 2^n candidates, an advantage bound exists but is unusable. 2. The simulated view is distinguishable. If B cannot simulate the challenge, random oracle or signatures seen by A, A’s advantage does not transfer. 3. The loss factor is ignored. Treating 128 bits as 128 bits when ℓ=q s is a parameter-selection error. 4. The assumption is weakened.…
